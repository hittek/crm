# S01: Report data models and registry skeleton

**Goal:** Migrate ReportDefinition and ReportRun Prisma models, implement the Report base class and registry, create the internal trigger endpoint, and seed the first built-in report.
**Demo:** curl -X POST /api/internal/run-report -H 'x-internal-secret: ...' -d '{"reportId": 1}' → {runId: 1, status: 'pending'}

## Must-Haves

- psql shows ReportDefinition and ReportRun tables; POST /api/internal/run-report returns {runId} and creates a ReportRun row; registry.get('daily-digest') resolves the class; existing /reports page still renders (no regression).

## Proof Level

- This slice proves: artifact + unit test

## Integration Closure

lib/reports/ is self-contained. Only consumers are the scheduler (S04), the API routes, and the UI (S06).

## Verification

- ReportRun table records every execution: status, duration, error, recipientCount. All changes visible via psql.
