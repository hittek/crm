# S04: Scheduler with per-org timing and idempotency

**Goal:** Install node-cron and wire a per-org hourly scheduler that fires report runs at each org's configured hour.
**Demo:** Container logs show 'scheduler_tick orgsChecked:1 triggered:1'; DB shows ReportRun row with status=delivered for today's window

## Must-Haves

- Scheduler initialises once at process start. At the configured hour a ReportRun row is created with status=delivered. Manual tick endpoint allows forcing a run without waiting for the hour. Double-fire within same windowKey returns already_delivered and creates no duplicate row.

## Proof Level

- This slice proves: DB + logs

## Integration Closure

lib/scheduler.js imports node-cron, prisma, and the executor directly (no HTTP). Initialized once per process from pages/api/health.js side-effect import. ReportDefinition.schedule JSON drives timing.

## Verification

- Scheduler init logged at startup. Each fired run logged with orgId, reportId, windowKey, duration, and status.
